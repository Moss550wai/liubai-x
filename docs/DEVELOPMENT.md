# 从「识别 AI」到「刷评论时无感」

这份记录整理于 2026-11-20，记录实际走过的路径和被放弃的方案。它是个人中文阅读偏好的开发过程，不是通用 AI 文本检测器的能力报告。代码、安装包和历史提交在本仓库；原始采集语料、逐条用户批注、训练模型中间产物和账号会话留在本地。

## 一开始：先看已有成品

需求起点是 X 评论区里的模板附和、生成腔和莫名接话。先下载并分析了 Clankoids 和其他候选的当时分发包，检查本地/服务端判断、中文覆盖、开关含义、数据路径和账号操作。

当时的检查没有找到一款能用现有证据承诺解决这些中文回复的成品：账号机器人判断不等于逐条低价值回复判断；英文套话规则不能直接视为中文能力；联网语义分类还引入延迟和数据外发。这里只总结 2026-11-19 保存样本的检查，不替任何产品的当前版本背书，也不复分发第三方扩展代码。

随后试过通过本机 CLI 调用较大模型来判断。常驻可以减少启动开销，但不能消除生成/调用延迟。这条路径没有成为最终浏览器推理链。

## 第一轮模型：小模型还可以更小

原本考虑几百 MB 的本地模型，后来把问题拆成稀疏中文文本分类：字符 n-gram + TF-IDF + 逻辑回归。没有 tokenizer 模型下载，没有神经网络运行时；最终浏览器只携带词表、IDF、线性权重和几段 JavaScript。

离线阶段也试过句向量、蒸馏、组合和短句专家。旧开发口径中，字符基线 AP 0.688、组合器 0.663、短句专家 0.633；这些是同一轮旧标签的开发数字，差距不能仅凭点估计就宣布显著。它们均以单条回复文本打分，增加结构没有证明能补齐新的输入信息。

## 真正的难点：标签和目标一直在澄清

早期开发资料为 842 条回复、52 个原帖，其中 782 条参与旧训练，大多数标签来自助手，最初只有 41 条用户确认。用户反复审查后发现，助手容易把带数字、专业词、第一人称或口语的技术附和当正常交流；这些表面特征都不能单独决定保留。

目标逐步从「是不是 AI」转为「值不值得读」：普通短赞同、感谢有社交价值；机械复述即使很短，也可能想收起。一个有效建议也可能被模型打高分，因此作者来源、阅读价值和模型分数始终不是同一个概念。没有把用户的「不确定，但不像 AI」擅自改成明确标签。

随机审计、模型分歧队列和验收候选用途不同：随机样本可用于估计特定抽样总体，分歧样本用来纠错，不能混为盲测。曾单独保留 180 条 / 20 个新原帖候选；后续个人工具路线没有拿它们做新模型验收，因此没有独立总体精度保证。

## 检验更聪明的特征，而不是继续堆分类器

冻结多语言 MiniLM，对回复与原帖的相关度、同话题难负例差值和检索排名做开发诊断。控制字符基线分数和回复长度后，AUC 约 0.48–0.53，区间宽、没有可靠条件增量。这个结果只约束当时的表征和数据，不能证明所有上下文方法都没用；但不足以承担额外模型大小和推理成本。

之后做过标签来源对照、技术帖分场景校准可行性和词面覆盖诊断。人工样本来源混合，不能把不同阶段的 AP 直接相比；技术帖样本不足以稳健地给独立阈值。词面覆盖在混合样本上有线索，技术帖主场景区间仍宽，所以都没有接入运行时。相关汇总见 [实验记录](EXPERIMENTS.md)。

用户授权后也重训过一版相同字符结构。在同一套更新标签的开发比较里，新版没有显示优势，因此留下实验、继续使用原字符基线。后续的 75 次临时标签来源诊断拟合也没有替换部署模型。不能把「最终停止训练」误写成「整个过程从未训练」。

## 转折：个人工具接受误伤

最终成本取舍改变：不再追求通用、跨话题、稳定学会偏好，而是让个人阅读少头疼。用户接受误伤，先用固定字符模型，默认阈值 0.30，另提供标准 0.45、保守 0.7304868 和滑块。

145 条混合人工参考中，激进档收起 59 条，其中 41 条按原标签应折叠、18 条原标签保留，样本精确率约 69.5%。它们混合 OOF、新帖和定向复核，不是随机日常时间线，不能宣传为实际「七成准确率」。模型会错、会漏，界面必须让误伤容易恢复。

一些低分的包装附和仍会放过。处理长期不想看的账号由用户自己使用 X 的屏蔽功能，插件既不批量拉黑，也不维护另一套账号黑名单。

## 浏览器工程里实际踩过的坑

模型导出成纯 JavaScript 后，321 条与 Python 原模型对分，最大绝对误差约 1.18e-8。词表为 5,703 项，字符 1–4 gram；NFKC、提及/URL 归一化、sublinear TF、IDF、L2 与线性分数都保持一致。

界面最初按每条回复附上提示条。开发中发现：Shadow DOM 事件重定向会影响 X 的点击处理；X 会改写 article 的 class；强改原 flex 排版会把正文挤窄。后来改用普通按钮、隔离事件、data 属性，并保护原生布局。账号屏蔽被明确移回 X 手动操作。

v1.0.1 根据真实使用反馈，默认保留父帖作者的补充/串文，并去掉模型放行项的多余「留白」标记和占位。

v1.0.2 又补上例外：作者如果回复已折叠内容，也一起收起。页面正文不能可靠给出准确父回复 ID，所以只被动读取 X 已发出的 TweetDetail 响应，桥接帖子 ID 与父回复 ID；不额外请求，不向扩展传正文响应或凭证，也不按 DOM 相邻位置猜。

v1.0.3 解决了更核心的体验问题：一排排折叠条本身也造成噪声。命中项不再留在阅读流里，而是集中到当前已加载内容底部，只保留一个总入口，一次展开全部、一次收起。展开后是连续文字，没有逐条小格子。X 继续管理原节点，插件保存临时文字快照，节点回收不丢已读内容、回滚不重复计数、换帖清空。

真实 X 使用绝对定位虚拟列表，隐藏 article 还要处理其单条容器，避免空洞；已在一个公开帖子上确认 8 条归集、单一入口、原位置零控件和零测量留白。只测一个帖子不能保证所有 X 布局都兼容。

v1.0.4 整理公开仓库、安装教程、开发记录和发行包，运行逻辑与 v1.0.3 相同。完整功能版本见 [CHANGELOG](../CHANGELOG.md)。

## 哪些算验证，哪些不算

- 离线浏览器测试覆盖点击、键盘、白名单、反馈、路由、虚拟节点回收、作者关系、文本转义、主题、窄屏和 600 条压力页。
- 纯模型评分与包含 DOM/布局/绘制的页面体验分别记录；一次测量不当成跨设备性能保证。
- 真实 X 记录与合成页面记录分开；X 自己的接口错误没有被算成扩展测试通过的零错误。
- 用户说「重新加载完好像无感了」是个人试用反馈，不是模型召回或精确率指标。

当前没有上线 LLM、cross-encoder、句向量模型、账号行为聚合、父帖文本分类、多场景模型或自动重训。下一步先根据实际使用缺口决定，不因为模型更复杂就默认应该换。
